# Архитектура

## Модули

```
Source/
├── VehicleSimCore/        чистый C++17, без Unreal — физика машины
├── RoadGenCore/           чистый C++17, без Unreal — трасса, профиль, рельеф, точки интереса
└── Peregon/               игра
    ├── Vehicle/            UPeregonVehicleMovementComponent (мост ядро ↔ UE), APeregonCar (салон, двери, приборы)
    ├── Player/             APeregonCharacter (пешеход)
    ├── Interaction/        IPeregonInteractable, канал трассировки Interact
    ├── Game/               GameMode (меню → дорога/полигон без смены уровня), PlayerController, HUD,
    │                       GameInstance (деньги, время), SaveGame, GameUserSettings
    ├── UI/                 SPeregonMenu (Slate: меню, новая игра, настройки, пауза)
    ├── Art/                UPeregonArtSubsystem (процедурные PSX-текстуры, материалы)
    └── World/              APeregonRoadWorld (стриминг чанков), APeregonServicePoint (АЗС/кафе),
                            APeregonSky (день/ночь), APeregonProvingGround
Source/VehicleSimCore/…/BodyModel.cpp  процедурная модель машины: цельный кузов, салон, моторный отсек
Source/PeregonEditor/      модуль редактора: создаёт мастер-материалы M_PSX2 и M_PSX2_Glass при запуске
Tools/CarPreview/          просмотр модели машины в браузере (без Unreal)
Content/Fonts/             Golos Text, Unbounded (SIL OFL, кириллица) — меню, HUD, таблички
Tests/                     CMake: VehicleSim (стенд + паспорт машины), RoadGen (геометрия трассы)
```

Ядро не знает про Unreal, поэтому его можно тестировать за полсекунды в CI, переиспользовать
на сервере для кооператива и при желании унести в другой движок.

## Единицы и оси

- Ядро — СИ (м, кг, с, Н, рад). Unreal — см и кг·см/с². Перевод только в компоненте (`MToCm`).
- Оси шасси как в Unreal: X — вперёд, Y — вправо, Z — вверх. Положительный руль — вправо.

## Кадр физики

```
UPeregonVehicleMovementComponent::TickComponent (TG_PrePhysics)
 ├─ для каждого колеса: луч от точки крепления вниз на (ход + радиус)
 │    → сжатие, скорость сжатия, скорость пятна (Vx, Vy) в системе колеса, тип покрытия
 ├─ vsim::Vehicle::Step(dt)
 │    ├─ руль (Аккерман), автомат, автосцепление, подвеска + стабилизаторы → нагрузка Fz
 │    └─ N сабстепов по 1/600 с:
 │         шины (релаксация + Пасейка) → сцепление (неявная «сцепка») → дифференциалы
 │         → вращение колёс, тормоза → топливо → пуск/остановка мотора
 │    └─ тепло и износ
 └─ силы подвески (в точке крепления) и шин (в пятне + TireForceHeightCm) → AddForceAtLocation
```

### Почему так устойчиво

- **Шина с длиной релаксации**: проскальзывание — состояние, которое интегрируется точной экспонентой.
  Нет деления на скорость у стоящей машины, нет взрыва при 30 FPS. Машина держится на уклоне на ручнике.
- **Сцепление, блокировки, раздатка** — неявная модель: момент, выравнивающий скорости за шаг,
  ограниченный ёмкостью. Не требует жёстких пружин и маленьких шагов.
- **Тормоз** может только остановить колесо, но не раскрутить назад — честная блокировка.

Проверено тестом: разгон 0–100 при 30 и 144 Гц отличается на 0.3%.

## Тесты

`Tests/VehicleSim` — плоский стенд (кузов с 3 степенями свободы, квазистатический перенос нагрузки)
и «паспорт» машины: тормозной путь, разгон, максималка, поворот, уклон, расход, перегрев, износ.
Любая правка физики, которая ломает паспорт, валит CI.

```
cmake -S Tests/VehicleSim -B build && cmake --build build && ./build/vsim_tests
```

## Что дальше по технике

- Async Physics Tick: шаг ядра на физическом потоке с фиксированным dt (сейчас — игровой поток + сабстепинг Chaos).
- Реакция на опору (толкать физические объекты колёсами) — третий закон Ньютона в компоненте.
- Конфиги машин в Data Assets вместо `Presets.cpp`; узлы и слоты поверх `VehicleCondition`.

## Мир дороги

`rgen::Route` — таблица осевой линии с шагом 2 м (план, высота, кривизна, уклон) и функция
`GroundHeight(S, T)`: полотно → обочина → кювет → естественный рельеф (2D-шум), плюс выравнивание
под площадками и улицами. `APeregonRoadWorld` режет маршрут на чанки по 250 м и держит 2 позади и
4 впереди игрока; новый чанк строится не чаще одного за кадр. Чанк — процедурные меши (асфальт,
гравий, трава — у каждого свой физматериал для шин) и инстансы (деревья, столбы, ЛЭП, заборы, крыши).

Чтобы перейти на реальные дороги, достаточно подменить `Route::BuildPlan()` полилинией из OSM.

## Модель машины

`vmodel::BuildSokol()` (VehicleSimCore) описывает кузов функциями: полуширина боковины H(x, z) с ребром,
завалом и скруглёнными углами, арки колёс, поверхности капота/крыши/багажника z(x, y), наклонная боковина
«оранжереи» и линейчатые поверхности стёкол. Двери, крылья, пороги — куски одной поверхности, поэтому кузов
цельный, а щели между панелями настоящие. У панелей есть толщина и изнанка (карты дверей, потолок).
Каждая подвижная часть (двери, капот, багажник, руль, стрелки, педали, рычаги, колёса) — отдельный узел со
своим началом координат; `APeregonCar` создаёт по `UProceduralMeshComponent` на узел и по секции на материал.

Правило ориентации треугольников (Unreal): лицевая сторона (A, B, C) — та, куда смотрит (C − A) × (B − A).
Тест `vmodel_tests` проверяет нормали, габариты, зазоры колёс в арках и наличие «мишеней» взаимодействия.
